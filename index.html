ℹ️ Hinweise zur Relationenmodell-Aufgabe

          
        

        

          

            Übertrage das ER-Diagramm manuell ins Relationenmodell. Trage für jede Relation den Namen und alle Attribute
            ein.
          

          
Wenn du fertig bist, klicke auf „Überprüfen“.

          
Zeichenlegende

          
    
            
  • 
              PS (Primärschlüssel) – mit der Checkbox PS markieren. In der Musterlösung
              unterstrichen dargestellt.
            
    • 
            
  • 
              FS (Fremdschlüssel) – mit der Checkbox FS markieren. In der Musterlösung
              blau mit ↑ dargestellt (eine andere gängige
              Darstellungsform ist eine
              gestrichelte Unterstreichung).
            
    • 
            
  • Ein Attribut kann gleichzeitig PS und FS sein (z. B. bei n:m-Beziehungen).
    • 
          

          
Fremdschlüssel umbenennen

          

            Falls ein Fremdschlüsselname mit einem bestehenden Attributnamen kollidiert, darf er umbenannt werden. Dabei
            muss der Prä- oder Postfix mit - oder _ vom Originalname getrennt sein (z. B.
            Klasse-SchülerNr oder SchülerNr_2). Ein Fremdschlüssel darf auch wie die Tabelle
            heißen, auf die er zeigt (z. B. Klasse statt Bezeichnung).
          

          
SQL erzeugen

          

            „SQL erzeugen“ macht aus deinen Relationen SQL-Code (CREATE TABLE) für SQLite. Dort wählst du
            die Datentypen; den Code kannst du kopieren oder als .sql-Datei speichern.
          

        

      

    


    
    

      

        

          
📚 Transformationsregeln: ERM → Relationenmodell

          
        

        

          
1. Entitätsklassen

          

            Jede Entitätsklasse wird zu einer eigenen Relation. Alle Attribute werden übernommen. Der Primärschlüssel
            (PS) bleibt bestehen.
          

          
2. 1:n-Beziehung

          

            Der PS der 1-Seite wandert als Fremdschlüssel (FS) in die Relation der n-Seite. Eigene
            Attribute der Beziehung kommen ebenfalls in die n-Seite.
          

          
3. 1:1-Beziehung

          

            Der PS einer Seite wandert als FS in die andere Relation. Eigene Attribute der Beziehung werden mitgenommen.
          

          
4. n:m-Beziehung

          

            Die Beziehung wird eine eigene Tabelle (Relation), die Beziehungstabelle. Sie heißt wie die
            Beziehung. Die PS beider beteiligten Entitätsklassen werden als FS übernommen und bilden gemeinsam den
            zusammengesetzten PS. Eigene Attribute der Beziehung werden ebenfalls aufgenommen.
          

          
5. Selbstbeziehung

          

            Sie wird wie jede andere Beziehung abgebildet. Weil der FS auf die eigene Relation zeigt, wird er umbenannt,
            z. B. SchülerNr-Freund.
          

          
6. Verbundschlüssel

          
Besteht ein PS aus mehreren Attributen, wandern als FS immer alle seine Attribute mit.
